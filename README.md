


# AWS 3-tier architecture (Terraform)

Web (Apache, Auto Scaling) -> App (Auto Scaling) -> DB (RDS PostgreSQL Multi-AZ + ElastiCache),
plus S3 + CloudFront for static content, DynamoDB, SES, Route 53 and CloudWatch.

## Layout

    bootstrap/               S3 bucket for remote state (run once, local state)
    templates/               EC2 user-data scripts (web, app)
    modules/                 reusable building blocks, no environment values inside
      vpc/  security-groups/  alb/  asg/  rds/  elasticache/
      dynamodb/  ses/  s3-cloudfront/  acm/  route53/  monitoring/
    environments/
      dev/                   own state, own terraform.tfvars
      prod/                  same code as dev, different values

Rule: modules never hardcode values. Each environment only wires modules together
and passes values through `terraform.tfvars`.

## Subnet layers (per AZ)

    public  : ALB, NAT gateway
    web     : Apache servers (private, egress via NAT)
    app     : app servers + internal ALB (private)
    db      : RDS + ElastiCache (no internet route)

## Run it

1. Create the state bucket:

       cd bootstrap && terraform init && terraform apply
       # note the state_bucket output

2. Put that bucket name in `environments/dev/backend.tf` (and prod).

3. Deploy dev:

       cd environments/dev
       terraform init
       terraform plan
       terraform apply

4. Open the `alb_dns_name` output in a browser. `/` returns "web tier ok",
   `/api/` returns "app tier ok" (placeholder pages: replace in templates/).

5. Destroy when done (dev costs money while running):

       terraform destroy

## Domain, HTTPS and email (optional)

Needs an existing Route 53 hosted zone. In `terraform.tfvars` set:

    enable_dns  = true
    domain_name = "novacart.app"

This creates ACM certificates, HTTPS on the ALB, `www.` -> ALB and `media.` -> CloudFront.
SES: add `ses_email_identities`; AWS emails each address a confirmation link.
New SES accounts start in sandbox mode: request production access in the console.

## Notes

- The DB password is generated by RDS and stored in Secrets Manager (see `rds_secret_arn`).
  The app role is allowed to read it. It never appears in the code or state.
- No SSH keys or port 22: use Session Manager (`aws ssm start-session --target <instance-id>`).
- ElastiCache has TLS enabled: your client must connect with TLS.
- The internal ALB is not drawn in the diagram. It gives the web servers one stable
  address for the app Auto Scaling group.
- Pinned to AWS provider ~> 5.0, Terraform >= 1.10 (S3 native state locking).
